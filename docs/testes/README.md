# Testes e avaliação (conforme o projeto)

Separe testes de software, análise experimental e avaliação com usuários. Use somente os planos que forem adequados ao método e ao escopo; nem todo projeto precisa de questionário ou teste com participantes.

## Testes de software

Registre requisito/cenário, versão do código, ambiente, dados de teste, passos, resultado esperado, resultado observado e evidência. Distinga testes unitários, integração, API, interface web, aplicativo móvel e ponta a ponta conforme existirem. Se houver Android e iOS, identifique em qual plataforma cada cenário foi executado.

O arquivo [`plano-e-evidencias-de-testes-template.md`](plano-e-evidencias-de-testes-template.md) oferece uma matriz inicial. Adapte tecnologias, camadas e comandos; não deixe os exemplos fictícios como resultados reais.

## Avaliação ou pesquisa com participantes

Use o [`roteiro-avaliacao-usuarios-template.md`](roteiro-avaliacao-usuarios-template.md) somente se a metodologia realmente envolver pessoas. Defina com a orientação os participantes, consentimentos, instrumento, coleta e tratamento de dados antes da atividade. Um formulário online é uma opção, não uma exigência universal. Proteja dados pessoais e não colete mais informações que o necessário.

Apresente resultados no documento acadêmico conforme o template institucional e a orientação da disciplina. Não afirme que um sistema foi validado apenas por existir um questionário ou uma demonstração.

**Exemplo fictício:** a equipe executa o mesmo cenário de consulta de empréstimos em um navegador e em um emulador Android, usando dados sintéticos. O relatório registra versões e resultados separadamente. Isso é teste técnico; não é avaliação com usuários nem aceite do cliente.
